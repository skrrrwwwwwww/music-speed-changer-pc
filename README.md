# Music Speed Changer (PC)

Настольный аналог Android-приложения **Music Speed Changer**: меняйте темп и
тон любого аудиофайла **в реальном времени**, без перекодирования и с
сохранением качества. Реализовано на Electron (интерфейс) + Python/Numpy
(аудиодвижок).

Лицензия: MIT.

```
Audio файл ─► [sinc] ─► [фазовый вокодер] ─► [sinc] ─► PortAudio
              ресемплинг     темп (тон      сдвиг тона
              к частоте карты сохраняется)  ±12 полутонов
```

## Возможности

| Функция | Описание |
|---|---|
| **Темп 0.25× – 4.0×** | Фазовый вокодер в реальном времени, высота тона не меняется |
| **Тон ±12 полутонов** | Независимо от темпа, с передискретизацией на лету |
| **Точный ввод** | Клик по цифре — поле ввода: темп и тон задаются с шагом 0.01 |
| **Петля A–B** | Выделяется мышью прямо на волне, склейка со сглаживанием |
| **Волна + playhead** | Огибающая из реальных данных файла, позиция с точностью до выборки |
| **Библиотека** | Обход музыкальных папок, группировка по папкам, поиск, переключение треков |
| **Автозапуск из проводника** | Двойной клик по треку в файловом менеджере сразу играет; отключается галочкой |
| **Пресеты и BPM** | Быстрые кнопки 0.5×…2×, подгонка темпа под заданный BPM |
| **Экспорт** | mp3 / m4a / flac / ogg / opus / wav через ffmpeg + rubberband |
| **Воспроизведение** | play / pause / stop, перемотка, повтор трека, выбор звуковой карты |
| **Горячие клавиши** | `Space`, `←/→`, `↑/↓`, `[` `]`, `L`, `B`, `Esc`, `Ctrl+O` |

## Установка

### Готовый пакет для Ubuntu (.deb)

```bash
sudo apt install ./music-speed-changer-<версия>-amd64.deb
```

Пакет ставится через системный менеджер пакетов, появляется в меню
приложений («Мультимедиа → Music Speed Changer») и регистрируется как
обработчик аудиофайлов — двойной клик по треку в файловом менеджере сразу
его запускает. Системный Python не требуется: аудиодвижок вложен
в пакет как отдельный исполняемый файл.

Программа ставится в `/opt/MusicSpeedChanger` — без пробелов в пути.
Это не украшение: Chromium местами разбирает путь к самому себе по
пробелам при запуске дочерних процессов и падает с
`failed to execvp: /opt/Music`. Если в системе осталась прежняя копия в
`/opt/Music Speed Changer`, её удаляет `postinst`.

Зависимости (ставится автоматически): `libportaudio2` — вывод звука,
`libgtk-3-0`/`libnss3`/`libgbm1` — окно Electron. `ffmpeg` числится в
`Recommends`: без него воспроизведение работает полностью, но экспорт
и импорт нестандартных форматов отключаются (кнопка «Экспорт» покажет
подсказку).

### Готовый пакет для Arch Linux

```bash
sudo pacman -U ./music-speed-changer-<версия>-1-x86_64.pkg.tar.zst
```

Ставит то же самое, что `.deb` на Ubuntu: `/opt/MusicSpeedChanger`, пункт
в меню, иконки в тему hicolor и `/usr/bin/music-speed-changer` для запуска
из терминала. SUID-права на `chrome-sandbox` выставляет сценарий установки
пакета, поэтому `--no-sandbox` не нужен.

Собрать такой пакет из исходников: `./scripts/build_arch.sh`
(нужны `base-devel`, `ffmpeg`, `portaudio`; результат — в `dist/`).

### Сборка пакета из исходников

```bash
./scripts/setup.sh          # venv + зависимости + electron
./scripts/build_deb.sh      # иконки, движок, .deb → dist/
```

Полностью автономный пакет (ffmpeg вложен внутрь, ~230 МБ вместо ~150 МБ):

```bash
MSC_BUNDLE_FFMPEG=1 ./scripts/build_deb.sh
```

Требования для сборки: Ubuntu 22.04+, `dpkg`, `fakeroot`, `curl`, `tar`,
`python3-venv`, `nodejs` 18+.

### Запуск из исходников

```bash
./scripts/setup.sh
npm start                 # или ./scripts/dev.sh
```

`npm start` уже передаёт Electron флаг `--no-sandbox`. Он нужен, потому что
Electron из `node_modules` лежит в пользовательских каталогах, и Chromium
считает такой путь небезопасным для SUID-песочницы и отказывается стартовать
с `FATAL:setuid_sandbox_host`. В установленном `.deb` песочница настроена
через `postinst`, поэтому там флаг не требуется.

Запуск с включённой песочницей (только если `node_modules/electron` принадлежит
root): `npm run start:sandbox`.

### Проверки

```bash
./scripts/test.sh           # 64 теста DSP и протокола, ~9 с, без звуковой карты
node scripts/e2e.mjs        # сквозной сценарий с реальной звуковой картой
```

Оба набора проверяют, что темп меняет длительность, а тон — высоту, что
позиция воспроизведения совпадает со звуком, что петля A–B зацикливается и
что экспорт даёт корректный файл.

## Архитектура

```
electron/          main.js       окно, меню, диалоги
                   preload.js    контекстный мост (contextBridge)
                   sidecar.js    запуск и обмен с python-процессом
renderer/          index.html    разметка
                   app.js        логика UI, волна на canvas, ручка темпа
                   styles.css    тёмная тема
python/msc/
  phasevocoder.py  потоковый фазовый вокодер (COLA, identity phase locking)
  sinc.py          ресемплинг Kaiser-sinc с переменным ratio
  stream.py        цепочка обработки канала, точная позиция источника
  engine.py        транспорт, поток рендера, аудио-колбэк
  sources.py       soundfile / ffmpeg, метаданные
  peaks.py         огибающая для отрисовки
  exporter.py      экспорт через rubberband или свой движок
  server.py        NDJSON-протокол поверх stdin/stdout
scripts/
  build_engine.py  сборка движка в один файл (PyInstaller)
  make_icon.py     генерация иконок без внешних зависимостей
  prepare_assets.sh иконки + статический ffmpeg
  build_deb.sh     сборка .deb
  e2e.mjs          сквозной тест через реальный сайдкар
```

### Что попадает в .deb

```
/opt/Music Speed Changer/          Electron + приложение
  └── resources/bin/msc-engine     аудиодвижок (PyInstaller, 37 МБ)
/usr/bin/music-speed-changer       симлинк на запускаемый файл
/usr/share/applications/*.desktop  запись в меню + MIME-типы
/usr/share/icons/hicolor/512x512/  иконка
```

Движок собран PyInstaller'ом в onefile: он не требует системного Python и
зависит только от `libc`/`libz`; PortAudio подгружается через `dlopen`,
поэтому `libportaudio2` объявлен в `Depends`. Версии библиотек в `Depends`
указаны без суффикса `t64` — на Ubuntu 24.04+ они разрешаются через
`Provides`, так что один пакет ставится и на 22.04, и на 26.04.

### Протокол

Python-процесс читает команды построчно из stdin и отвечает в stdout
(JSON в строку). Всё, что не является протоколом, уходит в stderr.

```jsonc
// команда
{"id": 1, "cmd": "set", "param": "speed", "value": 1.5}
// ответ
{"id": 1, "ok": true}
// событие
{"ev": "state", "state": { "position": 12.34, "playing": true, ... }}
```

## Ключевые инженерные решения

**Фиксированный синтезирующий хоп.** Синтезирующий хоп фазового вокодера
постоянен (256 отсчётов), а анализирующий равен `round(256 × rate)`. Благодаря
этому нормализация COLA не зависит от скорости, смена темпа не требует
пересборки буферов и не вызывает щелчков.

**Точная позиция источника.** `PhaseVocoder` считает поглощённые отсчёты, а
`StreamPath` вычитает упреждение всех последующих ступеней. Позиция в UI
совпадает со звуком с точностью ~0.1 % (проверено тестом), хотя сам файл
прочитан на ~0.2 с вперёд.

**DSP вне аудио-колбэка.** Real-time колбэк делает только `memcpy` из очереди;
FFT, ресемплинг и декодирование идут в отдельном потоке. Буфер — 8 блоков,
при опустошении рендерер будится немедленно (`Event.set()` из колбэка).

**Экспорт двумя способами.** `rubberband` (高质量, offline) или собственный
движок — экспорт получается ровно тем, что слышно. Оба режима покрыты тестами.

### Если приложение не запускается

Electron требует SUID-песочницу `chrome-sandbox` с правами `4755`.
`electron-builder` не выставляет их автоматически, поэтому пакет содержит
`postinst` (`scripts/postinst.sh`), который делает это при установке. Если
песочница потеряла права (например, после `cp -r` вручную), приложение падает
с ошибкой:

```
FATAL:setuid_sandbox_host.cc] The SUID sandbox helper binary was found,
but is not configured correctly.
```

Исправляется одной командой:

```bash
sudo chmod 4755 "/opt/Music Speed Changer/chrome-sandbox"
```

Диагностика запуска (движок, окно, среда, логи):

```bash
./scripts/diagnose.sh
```

Логи приложения: `~/.config/Music Speed Changer/logs/main.log`.

## Ограничения

* Диапазон темпа 0.25× – 4.0× и тона ±12 полутонов выбран так, чтобы
  фазовый вокодер работал с перекрытием ≥ 2 кадра (качество при крайних
  значениях ожидаемо ниже).
* В режиме `--silent` звук не выводится, но транспорт и таймлайн работают —
  удобно для CI и тестов.
* Пакет собран под x86_64. Сборка под arm64 возможна тем же скриптом
  на соответствующей машине (`electron-builder --linux deb --arm64`).
* Без `ffmpeg` (не установлен пакет `ffmpeg`) воспроизведение полноценно,
  но экспорт и форматы вроде `.m4a` недоступны.
